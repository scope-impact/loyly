01Scored · 3 Gondolin VMs

Terra black-box graders

Each shard gets only its selected Gherkin rules, a read-only candidate and a private room. For every item it copies the app into fresh writable runtime state, starts it, and observes HTTP responses and persisted effects without reading implementation source.

Measures
Room and day availability, confirmation and refusal, second slots, derived list/heater/billing views, release, and overlapping household requests. Item 01-010 repeats the race 100 times.
Evidence
One Allure result per item with Given/When/Then steps, request/response attachment, exact item tag and a surprises file. Cycle 06: ten passes; 01-011 remained pending for blind review.
Fails when
A Then is contradicted, missing or unobservable. A green candidate test suite cannot substitute for the public observation.

02Scored · fresh Sol VM

Blind refusal review

The reviewer sees only refusal.txt and question.txt. It has no plan, room configuration, candidate or previous grader transcript.

Measures
Can a resident identify a room, weekday and start time from the refusal alone? The controller replays exactly that request against a fresh app over HTTP.
Evidence
The raw refusal, one-line reviewer answer, HTTP response and supplemental Allure result for 01-011. Cycle 06: “pukuhuone 8 | Tuesday | 17:00” was confirmed.
Fails when
The answer needs hidden context, cannot name a request, or its exact request is not confirmed.

03Corroborating · Gondolin VM

Playwright + Chromium

A real headless browser opens the candidate's public schedule, chooses the Tuesday 17:00 room 8 slot, submits the native form as apartment 12, and checks the visible holding and all three derived views.

Measures
UI selection, HTTP confirmation, persisted schedule state, posted list, heater schedule, billing signal and browser errors.
Evidence
Before/after PNG screenshots, a Playwright trace ZIP, result steps and VM receipt. The pinned reassessment passed for item 01-003.
Fails when
The journey cannot complete or the displayed and persisted booking disagree.

04Corroborating · Gondolin VM

Node.js protocol race probe

For 100 fresh free slots, it starts two household POSTs before either response is read. After each pair it inspects the holder, booking record and all three derived views, then releases the winner.

Measures
Exactly one HTTP 201 and one held HTTP 409 per race; one persisted winner; coherent views; a free slot after release.
Evidence
JSON rows for all 100 races, Allure steps and VM receipt. The pinned reassessment passed 100/100 for item 01-010.
Fails when
Requests do not overlap, both confirm, neither confirms, the wrong household holds the slot, or views diverge.

05Diagnostic · Gondolin VM

OpenTelemetry live probe

A Node loader instruments the running candidate's HTTP server and sends OTLP traces and metrics to a local receiver inside the VM. The probe makes one real booking and checks its durable record and views.

Measures
A POST /api/bookings span and loyly.booking.request metric tied to the candidate digest, probe run ID and process PID.
Evidence
Raw OTLP JSON, booking observation, Allure steps and VM receipt. Cycle 06 saw HTTP 201, three spans and 17 metric rows for item 01-003.
Fails when
The span or metric cannot be tied to that process and booking. This is a diagnostic, not an extra scored item.
Scope
This loader probes the Node candidate; it does not establish JVM or Clojure profiling coverage.

06Collector · host process

Allure validator + legacy scorer

The host validates result JSON with Ajv, checks project-specific identities and attachment bytes, verifies exactly one grader result per selected item, then copies shard result directories into the combined grading room.

Measures
Schema validity, feature/story/item labels, required observation and steps, candidate and VM receipt digests, unique coverage, and unchanged filed score during reassessment.
Evidence
Combined Allure directory and digest, final verdicts, original 11/11 score, specialist manifest and 15-case report.
Fails when
Any result, attachment, binding or checklist item is missing, duplicated or changed. Specialist checks inform readiness; the original legacy scorer files the 11 item verdicts.
